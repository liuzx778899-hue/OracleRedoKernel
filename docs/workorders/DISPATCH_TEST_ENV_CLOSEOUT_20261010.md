用户授权：中央redo安全回收、正常多窗口连续运行、集中评审及测试环境验收优先推进。第一版已实现能力为验收范围；ARRAY/其它类型只按明确需求另列，长期平台、生产现场、D5不启动，TDE Issue #2继续搁置。唯一作者，原两份未跟踪交接文件保留。

## 当前缺口和选择

现有V6恢复状态虽持久化完整行、字典、事务及发现状态，物理配对、基线覆盖、字典维护和索引位置仍遍历旧raw；提交核验还逐级重现所有前窗。不能只修改保留数字或删除已消费文件。

优先实现可证明闭合的状态切点：从已经完整解析且目标/事件账/实际CPACK闭合的状态物化新的读取起点；不获取SQL真值作为生产行，不给旧raw补批新获取授权。存在相关未闭合事务/字典或仍需旧输入时拒绝切点并继续保留；保留必要边界成员，先做正常静态schema接续，不以放宽配对解决回收。旧提交以服务端核验后持久化的绑定证据保留可复核性，不用客户端计数或单个文件自报SHA替代核验。

## 顺序和出口

1. 内核切点及产品持久化接线：绑定来源、原可信基线、目标提交/事件账、实际ACK及producer摘要；先持久化可信切点，再提供明确可回收文件集合。回收仅作用于本任务中央副本，原冻结证据不删。
2. 必要正反例：删除可回收测试副本后独立进程恢复，续读完整新窗口，事件/前后像/目标账/CPACK不漏不重；缺ACK、切点毒化、错来源及未闭合依赖拒绝，零删除/零错误发布。针对改变的逻辑回归，不重跑旧矩阵。
3. 正常连续集成：同一固定source/采集计划跨多个窗口，以逐窗任务及可信前驱链接续；验证采集、解析、提交、实际ACK、背压释放和中央磁盘占用。必要未来新变化只生成一次，不重放旧DML；业务无变化时保持进程，不凭事件沉默认定失败。不扩强杀、多故障组合或性能调优。
4. 集中评审及测试环境验收：复用D1/D2/D4既有证据，记录候选提交/运行SHA和第一版边界。独立评审与作者测试分列，不以作者总结代替评审；一份统一反馈和两端STATUS。

资源沿用自有19c和固定helper；优先冻结样本离线开发，必要集成按需启动，日志保全后删helper并停库。正式制品来自完整提交树，失败追加，秘密脱敏。
